# Decisions

Choices where the spec was silent or had to be refined. Precedence: GOAL > TECH_SPEC > PRD > others.

| # | Decision | Why |
|---|---|---|
| D1 | Next.js 16.4.6 with `cacheComponents` **off** (the create-next-app default turns it on). | Every page is live, per-request state; Partial Prerendering adds Suspense constraints with no benefit here. |
| D2 | `REALTIME_MODE` defaults to `mock` when unset; `assertBootable()` (called from `instrumentation.ts`) refuses `NODE_ENV=production` + mock unless `ALLOW_MOCK_IN_PROD=1`. | Credential-less dev works out of the box, and a production deploy that forgets the variable fails loudly instead of silently using the mock. The e2e suite runs `next start` with `ALLOW_MOCK_IN_PROD=1`. |
| D3 | `TIMING_SCALE` env (default 1, max 1) multiplies every phase duration. | Lets e2e and `/try` tests run a full show in seconds without a second code path. Never set in production. |
| D4 | `PublicState` adds `premise`, `preset`, `isDemo`, `finale`, `i18n`, `option.boosted`; credits are `{name, bot}` objects instead of strings. | LOBBY needs the premise card, Judge Mode needs the boost tag, and bots must be labelled 🤖 everywhere, which needs a typed flag rather than a name convention. |
| D5 | `CP:Idea` carries `roundNo` instead of `roundId`. | Clients only know the round number; the server resolves the round from (show, roundNo). |
| D6 | `CP:Moderation` hides ideas by `{userId, clientMsgId}` (and `hideUserIds` for bans), not by server idea id. | Clients render ideas straight from realtime messages and never see server ids. |
| D7 | Manual mode (`autoAdvance=false`): STORM and VOTE still end on their timers (players see countdowns); REVEAL holds until the host presses **Next round**; LOBBY and FINALE always wait for the host. | Keeps countdowns honest while giving the host control of pacing between rounds. |
| D8 | Extra engine effects `REPLACE_OPTION` (veto) and trigger types `HOST_SET_AUTO`, `HOST_SET_VOICE`. Re-roll returns to DISTILL with mode `reroll` and clears votes. | Veto/re-roll/toggles are host triggers in the PRD; modelling them as machine transitions keeps one code path and versioned state. |
| D9 | Votes are HTTP-only (secret, authoritative); everything players *see* is delivered through the realtime transport. | As designed in NEXCONN_INTEGRATION §6. |
| D10 | AI modules are DB-free (`src/lib/ai/types.ts`); the engine loads inputs, persists outputs and recomputes counts/credits from the DB. | FR-14: LLM output is untrusted; keeps AI code unit-testable with fixtures. |
| D11 | Process singletons (DB, mock bus, ticker, mutexes, rate limiters, embedding cache) live on `globalThis`. | Next bundles `instrumentation.ts` and route handlers separately; module-level state would not be shared. |
| D12 | Open Channel metadata keys use `cp_phase`, `cp_prompt`, … (underscore) instead of `cp.phase`. | Nexconn metadata key charset is letters, digits and `+ = - _` (docs/NEXCONN_SDK_NOTES.md). |
| D13 | Embeddings unavailable/failed/late (>0.8 s) → distill clusters local hashed bag-of-words vectors on a stride sample of ≤120 ideas (local thresholds 0.25 assign / 0.30 merge, calibrated on the 200-idea fixture; provider vectors keep 0.62 / 0.72). Provider and local vectors are never mixed; after a provider failure embeddings are skipped for 15 s. | Implements B2's "LLM-only path" without dropping clustering: no embedding provider is called, the LLM still writes the labels. |
| D14 | Forced `tool_choice` is used for Haiku-class models; Sonnet/Opus-class models get `auto` + an instruction (they reject forced tool choice). A 400 about tool_choice/thinking/effort is learned per model id and retried once. | Matches the current Claude API behaviour; keeps model ids env-driven. |
| D15 | Re-roll retires old options (`slot=null`, `vetoed=true`, `rank+100`) instead of deleting them; votes are deleted. Veto replacement prefers a backup of the same kind with a label not already on the ballot. | `receipts.option_id` references options; the ballot keeps 2 crowd + 1 wildcard. |
| D16 | Effect idempotency claims carry `data.done`; an unfinished claim older than 5 s can be re-claimed, and `recoverInterruptedEffects()` runs at boot. | A restart mid-effect (A10) re-runs lost CLOSE_VOTE / narration / receipts / finale exactly once. |
| D17 | `PublicState.finale` is present in FINALE/ENDED with `recap`/`tagline` = "" until the finale generator returns (then a new version is published). | UI shows "the narrator is writing…" instead of a blank. |
| D18 | Ingest checks the `(user, clientMsgId)` duplicate before phase and rate-limit checks and serialises same-key deliveries in-process; `source='bot'` skips participant/mute/ban/rate-limit checks but keeps the round cap and the filter. | Webhook + HTTP double delivery (B4) must report ok twice and insert once, even within milliseconds. |
| D19 | Display names are filtered in strict mode; the phone-number pattern blocks runs of ≥7 digits. | Names and ideas share one filter (AI_PROMPTS §7). |
| D20 | FEATURE_MULTILINGUAL: languages = joined, non-banned participants' 2–3 letter codes ≠ show language (max 6); one `translateBundle` call per (room, round, language set, content version), never awaited by a publish — the state goes out first and a re-publish carries `i18n`. `i18n` travels only in CP:State (no metadata key). In LLM_MODE=mock translation returns `{}`, so flag-on needs live keys to show translations. | Translation must never delay a phase change (rule 6). |
| D21 | Open Channels of rooms that have been ENDED for 2 minutes are destroyed by a ticker sweep (one claim row per room). | Free plan caps concurrent Open Channels at 50; the sweep is restart-safe and leaves no per-room timers. |
| D22 | Clustering of local hashed vectors compares sparse non-zero entries only (bit-identical output). | 1,500 distinct ideas: 3.5 s → 1.8 s distill worst case. |
